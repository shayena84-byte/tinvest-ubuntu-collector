# Market Recorder v1.5.0: контроль качества и веб-дашборд

Версия v1.5.0 продолжает локальный пятиминутный сбор SBER/TQBR и Омега БО-01/TQCB через существующий SOCKS5 192.168.202.50:1080. Новые функции — аудит достоверности стакана, история аномалий и защищённая локальная веб-панель. **Без торговых операций, без подключения OpenAI, без вывода токенов, без изменения Production-счетов**.

## Установка/обновление существующей v1.4.0

~~~bash
cd ~
wget -O tinvest_ubuntu_collector_v1.5.0.zip https://github.com/shayena84-byte/tinvest-ubuntu-collector/releases/download/v1.5.0/tinvest_ubuntu_collector.zip
unzip -o tinvest_ubuntu_collector_v1.5.0.zip
cd tinvest_ubuntu_collector
bash install_market_quality.sh
sudo loginctl enable-linger "$(whoami)"
~~~

Установщик:
1. Проверяет файлы и выполняет все офлайн-тесты из релиза.
2. Временно останавливает таймер сбора, чтобы исключить запись при обновлении схемы SQLite.
3. Делает резервную копию SQLite через Python SQLite Backup API в ~/.local/share/tinvest-market/backups/.
4. Обновляет сборщик, таблицы и схему базы с версии 1 до версии 2, **не удаляя исторические записи**.
5. Создаёт user-службу dashboard, доступную только на 127.0.0.1:8787.
6. Возобновляет пятиминутный сбор. Ранее существовавшие торговые таймеры остаются выключенными.

Если сбой произойдёт до миграции, данные останутся в исходной базе. Если после резервного копирования возникнет ошибка, для восстановления используйте сохранённый файл .sqlite3 с учётом остановки сервисов. Не заменяйте работающую WAL-базу обычным копированием.

## Доступ к панели из Windows 11

На Windows откройте терминал PowerShell/Windows Terminal и выполните:

~~~bash
ssh -L 8787:127.0.0.1:8787 user@IP_ВАШЕГО_UBUNTU
~~~

Подставьте фактический адрес Ubuntu Server (не SOCKS5-прокси). Пока SSH-сессия открыта, перейдите в браузере Windows на:

http://127.0.0.1:8787

Трафик интерфейса проходит по SSH. Прямая публикация порта в Интернет и открытие порта на роутере **не требуются**.

Проверка службы:

~~~bash
systemctl --user status tinvest-sandbox-dashboard.service --no-pager
systemctl --user list-timers 'tinvest-sandbox-market*'
journalctl --user -u tinvest-sandbox-market.service -n 60 --no-pager
journalctl --user -u tinvest-sandbox-dashboard.service -n 40 --no-pager
curl -sS -I http://127.0.0.1:8787
python3 ~/tinvest-collector/market_recorder.py report --hours 24
~~~

Веб-интерфейс автоматически обновляется раз в минуту, SQLite-данные приходят каждые 5 минут, когда работает таймер.

## Что считается пригодной рыночной информацией

Версия 1.4 ошибочно читала временную метку REST-стакана из поля time. В GetOrderBook корректное поле — **orderbookTs**. Теперь оно читается в первую очередь; time оставлено только как совместимость для других форматов. Отсутствующую метку нельзя подменять текущим временем.

Снимок имеет один статус:

| Статус | Условие | Использование |
|---|---|---|
| valid | Есть bid и ask, bid < ask, подтверждённое время стакана не старше 15 минут | Можно включать в статистику ликвидности |
| stale | Время стакана старше 15 минут | Только архив, не торговые сигналы |
| unverified | Нет времени, время будущего, отсутствует одна сторона | Только архив и диагностика |
| invalid | Bid >= Ask (пересечённый либо заблокированный стакан) | Только архив и журнал аномалий |

Возраст **последней сделки** отслеживается отдельно. Для редкой облигации отсутствие сделок само по себе не делает свежий непротиворечивый стакан недостоверным. Не проверяются все возможные микроструктурные аномалии: это базовый фильтр качества, а не гарантия исполнения по определённой цене.

История в БД v1.4 сохраняется. Её старые записи после миграции консервативно помечаются как unverified или invalid (если bid >= ask), поскольку исходная версия не читала orderbookTs. Поэтому первое время доля подтверждённых снимков может быть низкой. Новые замеры получают полноценную проверку.

## SQLite и API панели

База: ~/.local/share/tinvest-market/market.sqlite3 (права 600). В схему добавлены колонки quality_status и quality_reason в snapshots и новая таблица anomalies, связанная со snapshot_id. Журнал аномалий сохраняет время, причину и статус, но не токены.

Панель доступна только на localhost:

- GET / — локальный HTML
- GET /dashboard.js — локальный JavaScript
- GET /api/market?hours=24 — только чтение, JSON с обобщёнными данными и историями (варианты 6, 24, 72 или 168 часов)
- POST/PUT/DELETE — запрещены

В UI отображаются четыре графика: цена сделки, лучшая цена покупателя и продавца, спред, суммарный объём первых десяти уровней. Для спреда, глубины и bid/ask используются **только** valid. На графике последней цены все сырые наблюдения показаны как ориентир, подтверждённые выделены отдельно. Не делайте выводов о доходности по одному снимку или только по последним сделкам.

Время на веб-панели показывается по Москве; в SQLite всегда UTC.

## Экспорт данных

~~~bash
python3 ~/tinvest-collector/market_recorder.py report --hours 24
python3 ~/tinvest-collector/market_recorder.py export --hours 168
~~~

CSV сохраняет первоначальные цены и новые quality_status/quality_reason. Базу и резервные копии не размещайте в публичном GitHub.

## Управление

Остановить только панель, оставив сборщик активным:

~~~bash
systemctl --user disable --now tinvest-sandbox-dashboard.service
~~~

Остановить сборщик:

~~~bash
systemctl --user disable --now tinvest-sandbox-market.timer
~~~

После перезагрузки Ubuntu пользовательские службы продолжат работу, если настроен linger. Панель ни при каких обстоятельствах не включает старый AI Trader.

## Известные ограничения

- Программа не управляет инвестициями и не выставляет заявки.
- Даже статус valid означает прохождение перечисленных проверок, но не достоверность всей биржевой микроструктуры и не гарантию доступности цены.
- Биржевые данные могут быть задержаны, ложные дисбалансы стакана возможны во время аукционов и при неполных данных.
- Дашборд получает только локально сохранённые измерения; прямых сетевых запросов к банку из браузера нет.
- Не реализована автоматическая очистка SQLite по сроку, поэтому следите за свободным диском и резервными копиями.
- При повторном запуске записи за одну пятиминутку обновляются атомарно, а предыдущая аномалия для этого слота заменяется новым результатом.
- Тесты GitHub Actions используют синтетические API-ответы. Реальное обновление на вашем Ubuntu нужно проверить по журналу после установки.
