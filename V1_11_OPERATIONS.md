# v1.11.0 — надёжность, журнал исполнения и автономные проверки

Версия объединяет исправления v1.10 и новые инструменты анализа. Торговля
по-прежнему разрешена только через T-Invest Sandbox. OpenAI API не нужен для
аудита базы, симуляции, просмотра панели и отдельного наблюдения за портфелем.

## Что изменилось

- Возраст стакана пересчитывается по биржевой метке `book_time_utc` при каждом
  использовании. Свежая запись в SQLite не делает старый стакан свежим.
- Общий поиск по UID/ISIN/тикеру и торговой доске; неоднозначность блокируется.
- Общая политика для облачного, локального и исторического алгоритмического
  агента: до 10% капитала на покупку, 50% общей экспозиции, 3% дневного убытка,
  не более трёх заявок в день. Более строгие пользовательские настройки сохраняются.
- Любая отправка дополнительно проверяет живой стакан, точный инструмент,
  портфель, доступные лоты и статус торгов. Используются лимитные Sandbox-заявки
  по отображаемому ask/bid, чтобы ограничить цену. Исполнение не гарантируется.
- Клиентский UUID сохраняется отдельно от биржевого идентификатора. После
  тайм-аута статус запрашивается с явным `orderIdType`; неизвестный результат
  блокирует новые заявки. Частичные исполнения записываются идемпотентно.
- Лимит OpenAI действует на все генерации, включая `dry-run` и ошибки. Запрос
  резервируется в SQLite до передачи. Между обращениями по умолчанию 30 минут.
- Единый установщик проверяет импорт модулей из установленного каталога,
  делает резервные копии кода и SQLite и сохраняет конфигурацию и секреты.
- Выпуск собирается из тега; ZIP и SHA-256 не заменяются последующими коммитами.

## Обновление существующей установки

Выполнять от того же обычного пользователя Ubuntu, который запускал предыдущую
версию. Не использовать `sudo` для установщика.

```bash
cd ~
curl -fL --retry 3 -o tinvest_v1.11.0.zip https://github.com/shayena84-byte/tinvest-ubuntu-collector/releases/download/v1.11.0/tinvest_ubuntu_collector.zip
curl -fL --retry 3 -o tinvest_v1.11.0.zip.sha256 https://github.com/shayena84-byte/tinvest-ubuntu-collector/releases/download/v1.11.0/tinvest_ubuntu_collector.zip.sha256
python3 - <<'PY'
import hashlib
from pathlib import Path
expected=Path('tinvest_v1.11.0.zip.sha256').read_text().split()[0]
assert hashlib.sha256(Path('tinvest_v1.11.0.zip').read_bytes()).hexdigest()==expected, 'Checksum mismatch'
PY
mkdir -p tinvest-v1.11.0-source
unzip -o tinvest_v1.11.0.zip -d tinvest-v1.11.0-source
cd tinvest-v1.11.0-source/tinvest_ubuntu_collector
bash install_v1_11.sh
python3 ~/tinvest-collector/system_status.py
```

Установщик отключает торговые таймеры, проверяет обе блокировки движков и
отказывается обновлять код, если другой цикл ещё выполняется. Остановленные
службы сбора и панели восстанавливаются; торговля автоматически не включается.
`--no-services` предназначен для изолированной файловой установки: в этом
режиме состояние служб не проверяется и не меняется.

Файлы ключей, токенов, `proxychains.conf`, TLS bundle, пользовательские настройки
и systemd override остаются на прежних местах. Резервная копия кода и согласованные
SQLite-копии находятся в каталоге `~/tinvest-collector-backups/`; точный путь
выводится установщиком. Схема рыночной базы обновляется до v3 первым запуском
сборщика без удаления истории. Новое поле `lot` заполняется ответом API;
для старых данных неизвестный размер лота не угадывается.

Старые имена установщиков оставлены как совместимые входы в единый установщик.
Переходить последовательно через каждый старый релиз больше не требуется.

## Независимое наблюдение за Sandbox

Наблюдатель не читает ключ OpenAI, не вызывает модели и работает даже при
`enabled=false` у торгового агента. Требуются настроенный Sandbox-счёт, его
отдельный токен, сеть и действующая конфигурация SOCKS5/TLS.

```bash
SSL_CERT_FILE="$HOME/.config/tinvest-readonly/ca-bundle.pem" \
proxychains4 -f "$HOME/.config/tinvest-readonly/proxychains.conf" \
python3 ~/tinvest-collector/sandbox_supervisor.py run
systemctl --user enable --now tinvest-sandbox-supervisor.timer
journalctl --user -u tinvest-sandbox-supervisor.service -n 40 --no-pager
```

По умолчанию режим `observe`: только чтение у брокера, сверка статусов заявок,
запись портфеля и сигналов риска. Он не выставляет и не отменяет заявки.
Таймер наблюдения при обновлении оставляется выключенным до указанного запуска.

Дополнительный режим `protect` включается оператором через файл
`~/.config/tinvest-readonly/supervisor.json`:

```json
{"mode":"protect","stop_loss_fraction":0.025,"trailing_stop_fraction":0.025}
```

В нём допускаются отмена незавершённой заявки старше 30 минут и продажа
виртуальной позиции при достижении порога потерь/трейлинга. Покупок нет.
Общие лимиты заявок, пауза между ними, подтверждение торгов и свежести данных
сохраняются: они могут заблокировать защитный выход. Отказ записывается в журнал.
Дневной порог ограничивает новые покупки; он не гарантирует предельную просадку.

## Журнал и панель

`~/.local/share/tinvest-market/trading.sqlite3` содержит:

| Таблица | Содержимое |
|---|---|
| cycles | Данные, решение, результат проверки, версия кода и хеш инструкции |
| model_calls | Все попытки генерации, резерв бюджета, токены и известная стоимость |
| orders / fills | UUID запроса, биржевой ID, частичные исполнения и комиссия |
| portfolio_samples | История виртуального капитала и обезличенных позиций |
| events / heartbeats | Причины отказов и последние наблюдения служб |

Номера брокерских счетов, API-ключи и заголовки авторизации не сохраняются.
Журнал содержит частные финансовые данные; файлы имеют права 600, каталоги 700.
Не загружайте рабочую базу или конфигурацию в публичный репозиторий.

Панель: `http://127.0.0.1:8787`, через существующий SSH-туннель. Добавлены
состояние служб, бюджет API, капитал, решения и исполнения. Панель только читает
базы, не вызывает внешние API и не управляет торговлей. Статусы показывают
последние наблюдения, а не гарантируют текущую сетевую доступность.

```bash
python3 ~/tinvest-collector/v19_health.py
python3 ~/tinvest-collector/offline_market_audit.py --hours 168
python3 ~/tinvest-collector/system_status.py
```

## Бюджет OpenAI

До 24 попыток в календарный день МСК, в том числе ошибки и `dry-run`; интервал
по умолчанию 30 минут. Действует атомарная резервация: параллельные ручные запуски
не обходят ограничение. `dry-run` не отправляет брокерские заявки, но расходует API.
Полностью автономные проверки — `offline_market_audit.py`, `offline_replay.py`
и `decision_providers.py --fixture ... --context ...`.

Параметры: `~/.config/tinvest-readonly/model-budget.json`. Ключи необязательны:

```json
{"max_calls_per_day":24,"min_interval_minutes":30,"max_input_tokens":24000,"max_output_tokens":2400}
```

Без подтверждённых тарифов стоимость показывается как неизвестная. Для денежного
ограничения задайте `max_cost_usd_per_day`, `priced_model`,
`input_usd_per_million` и `output_usd_per_million` по актуальному тарифу выбранной
модели. Если тариф не задан или модель другая, денежный лимит блокирует запрос.
На неуспешную попытку сохраняется полный резерв; неизвестная стоимость не считается
нулевой. Снижение лимитов действует сразу, увеличение выше жёстких потолков не допускается.

Ошибка `insufficient_quota` / `credit_balance_exhausted` требует явного сброса
после восстановления биллинга:

```bash
python3 ~/tinvest-collector/openai_quality_trader.py reset-api-block
```

Это не включает торговлю и не мешает независимому наблюдателю.

## Автономное воспроизведение и сравнение

```bash
python3 ~/tinvest-collector/offline_replay.py --hours 168 --strategy compare
python3 ~/tinvest-collector/offline_replay.py --strategy recorded --fee-bps 5 --slippage-bps 5 --latency-seconds 30
```

Сравниваются записанные одобренные решения, контрольная EMA(9/21) и удержание
актива с общей политикой риска. Новых ответов модели симулятор не создаёт.
Если записанных решений ещё нет, это явно указано. Для исполнения используется
только последующий наблюдаемый стакан, учитываются размер лота, обе стороны,
доступная глубина, частичное исполнение, комиссия и заданная задержка.
Неисполненный остаток снимается в модели через 30 минут.

Результат — JSON с кривой капитала, просадкой, исполнениями, комиссиями и причинами
отказов. Рыночная и торговая базы открываются только на чтение. Облигации и бумаги
с неизвестными единицами/лотностью исключаются. Текущие метаданные инструмента
не восстанавливают исторические изменения размера лота.

Пятиминутные снимки не описывают движение внутри интервала, очередь заявок и
скрытую ликвидность. Параметры комиссий и проскальзывания — предположения сценария.
Результат не является доказательством доходности или точной моделью биржи.

## Проверка перед торговлей

Сначала проверить наблюдение и качество стаканов. После восстановления OpenAI
выполнить один `dry-run`, учитывая расход API и его интервал. Проверить журнал,
сверенные заявки и эффективные риск-лимиты. Отдельное включение агента:

```bash
systemctl --user enable --now tinvest-sandbox-openai.timer
```

Остановка всех активных движков, включая опциональную защиту:

```bash
systemctl --user disable --now tinvest-sandbox-openai.timer tinvest-sandbox-ai.timer tinvest-sandbox-local-ai.timer tinvest-sandbox-autotrader.timer tinvest-sandbox-supervisor.timer
```

Не удаляйте `state.json` при неизвестном исходе заявки. Сначала сверить её через
наблюдатель и журнал. Для отката остановить службы, восстановить согласованную
копию кода и при необходимости базы из одного резервного каталога; старый код
может не понимать новую схему. Ключи и настройки при откате не заменять.
