# v1.11.1 — изоляция автотестов и исправление журнала

В v1.11.0 два теста модельного агента записывали фиктивные решения HOLD в
рабочий SQLite-журнал пользователя, а тест сборщика мог обновить его служебную
отметку. Ответы модели и брокера в этих тестах подменялись: платных обращений к
OpenAI и торговых операций не было. Запись от 12 ноября 17:42 UTC с причиной
«Наблюдение без сделки» относится к такому тесту, а не к реальной генерации.

## Исправление

- Установщик и CI запускают тесты через `run_offline_tests.py`: домашний каталог
  подменяется временным до импорта модулей, сетевые соединения запрещены.
- Тесты с записью журнала дополнительно используют собственные временные базы
  даже при ручном запуске обычного `unittest`.
- После резервного копирования установщик удаляет только записи, точно
  совпадающие с двумя известными фикстурами v1.11.0: `dry-run`, UID `UID`,
  синтетический контекст и полный текст тестового решения. Записи, связанные
  с обращением к модели, заявкой или событием, всегда сохраняются.
- Рыночная история, реальные решения, заявки, квоты, ключи, прокси и настройки
  не очищаются. Временная служебная отметка заменится следующим запуском сборщика.
- Существующий релиз v1.11.0 не перезаписывается.

## Обновление

Выполнять от обычного пользователя Ubuntu, от которого работает система:

```bash
(
set -e
TIN_UPDATE_DIR=$(mktemp -d "$HOME/tinvest-update-v1.11.1.XXXXXX")
cd "$TIN_UPDATE_DIR"
TIN_RELEASE_URL="https://github.com/shayena84-byte/tinvest-ubuntu-collector/releases/download/v1.11.1"
curl -fL --retry 3 -o tinvest_ubuntu_collector.zip "$TIN_RELEASE_URL/tinvest_ubuntu_collector.zip"
curl -fL --retry 3 -o tinvest_ubuntu_collector.zip.sha256 "$TIN_RELEASE_URL/tinvest_ubuntu_collector.zip.sha256"
sha256sum -c tinvest_ubuntu_collector.zip.sha256
unzip -q tinvest_ubuntu_collector.zip
cd tinvest_ubuntu_collector
bash install_v1_11.sh
)
```

Число удалённых фиктивных записей выводится в `test_fixture_cleanup.removed`.
Перед очисткой установщик сохраняет копию рабочей базы вместе с резервной
копией кода. Торговые таймеры после обновления остаются выключенными.
Наблюдатель при обновлении останавливается и требует повторного включения:

```bash
systemctl --user enable --now tinvest-sandbox-supervisor.timer
systemctl --user start tinvest-sandbox-supervisor.service
journalctl --user -u tinvest-sandbox-supervisor.service -n 30 --no-pager
python3 ~/tinvest-collector/system_status.py
```

Режим наблюдения по умолчанию — `observe`; он не выставляет и не отменяет заявки.
Покупки/продажи автоматически не включаются.

## Отдельная проверка журнала

```bash
python3 ~/tinvest-collector/test_data_cleanup.py
```

Команда только показывает кандидатов. Явное `--apply` удаляет подтверждённые
фикстуры после создания отдельной резервной копии. При обычном обновлении
этот дополнительный запуск не требуется.

Полное руководство по системе: [V1_11_OPERATIONS.md](V1_11_OPERATIONS.md).
